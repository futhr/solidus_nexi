# Release audit — 6 September 2026

This audit covers the Nexi client, Solidus adapters, checkout and refund services, webhook processing, recovery tasks, migrations, tests, CI, documentation, and gem packaging. The candidate remains `0.1.0.alpha.1`. No tag, push, or publication was performed.

## Findings addressed

Severity describes the possible effect before the fix, not a claim that the issue occurred in a store.

| Priority | Finding and correction | Commit |
| --- | --- | --- |
| High | Provider amounts could be truncated by `Integer(Float)`. Require integer JSON amounts, reject non-finite local money, and reject malformed charge/refund collections. | `34aaabc` |
| High | TLS errors escaped the client error handling. Classify retrieval failures as retryable and mutations as uncertain; explicitly disable transport retries. | `9da7add` |
| High | A malformed cancellation success became a definitive rejection. Preserve the unknown outcome and prevent replay. | `54e317e` |
| High | Gateway verification could accept historical reservation/charge totals after cancellation or refund. Check current financial state, local amount, payment reference, and order context. | `9d0212a` |
| High | Duplicate inserts could abort an enclosing PostgreSQL transaction. Use savepoints and preserve unrelated validation errors. Regression tests exercise actual unique constraints. | `684fa21` |
| High | Recovery could bind an identity before validating it, miss a crashed dispatched operation, or overwrite newer financial totals. Validate before binding, recover stale operations and IDs held only on operations, and retry regressing snapshots. | `aeb2400` |
| Medium | Cancelled/expired refunds could remain pending; an old failed attempt could hide a pending retry. Handle terminal outcomes and prioritize work still in progress. | `0b5bee5` |
| High | Checkout expiry was treated as proof that no payment occurred. Require a post-expiry financial snapshot before replacement; keep dispatched unknown creates blocked. Only never-dispatched intents can be abandoned automatically. | `b5e4d0b` |
| Low | Checkout lookup queried operations once per payment; serializer checks rechecked arithmetic they had just constructed. Use one query and remove those redundant checks. | `65282bc` |
| Medium | Development followed an unreleased Solidus branch and excluded Rails 8. Use published Solidus gems by default, support Rails 8.0/8.1, update development dependency floors, and expand CI. | `ad9082f` |
| Low | `ruby -S bundle` could parse a binary version-manager shim as Ruby. Invoke Bundler through the appropriate executable. | `511cb97` |
| Medium | Broad package globs included hidden files and followed symlinks. Restrict shipped file types, exclude symlinks, and verify archive entries, metadata, and bytes against source. | `5301625` |

Documentation was shortened where it repeated the same guarantees or described implementation details without helping the reader. The architecture page now points to the relevant code and explains the failure paths. The operating guide no longer describes checkout expiry as safe evidence for abandoning a dispatched payment. This is an editorial assessment, not an attempt to determine who wrote the original text.

## Dependency review

The development bundle was refreshed against RubyGems. The primary local environment resolves Solidus 4.7.0, Rails 8.1.3.1, solidus_support 0.15.0, solidus_dev_support 2.12.0, dotenv 3.2.0, and WebMock 3.26.4. Rails 7.2.3.2 and 8.0 were also tested. `Gemfile.lock` remains untracked, as in the existing extension workflow; each CI matrix entry resolves its compatible bundle.

The latest published development helper still constrains Puma below 7. It also holds back parts of the test and lint toolchain. For example, the compatible RuboCop Rails version is 2.36.0 rather than the newer 2.37.0. Those constraints were not bypassed by patching third-party gemspecs.

The unfiltered RubySec audit reports two Puma 6.6.1 advisories:

- [CVE-2026-47736](https://github.com/puma/puma/security/advisories/GHSA-qpgp-93vx-g8v8): memory exhaustion in PROXY protocol v1 parsing.
- [CVE-2026-47737](https://github.com/puma/puma/security/advisories/GHSA-2vqw-3mp8-cgmx): repeated PROXY protocol headers on a persistent connection.

Both require explicitly enabling PROXY protocol v1. This repository's tests do not enable it, and Puma is not a dependency of the published runtime gem. The existing exceptions are now documented together in `.bundler-audit.yml`; remove them when the development helper accepts Puma 7.2.1 or newer patched releases. The configured audit passes with those two exceptions. This is not an unqualified clean dependency audit.

GitHub Actions pins were checked against the latest releases: checkout v7.0.1, setup-ruby v1.321.0, and codecov-action v7.0.0 were already current. Runtime version ranges remain bounded to Solidus 4.x and Rails below 8.2. Ruby 3.2 and Rails 7.2 are compatibility targets, not recommendations for new deployments.

The Rails 8.1/SQLite run measured 97.74% line coverage and 82.65% branch coverage, above the configured thresholds. RuboCop reported no offenses. Eager loading passed; its only warning concerns optional patch directories in the upstream legacy-promotions extension.

Normal tests used synthetic data and mocked Nexi HTTP responses. No Nexi merchant lifecycle was run during this audit. The database servers used for local checks were disposable containers.

## Before publication

- Complete the merchant TEST lifecycle in [Testing](testing.md), including hosted card entry, webhook delivery, capture, cancellation, refund, and failure flows.
- Run the expanded GitHub Actions matrix on the reviewed commit. Local testing does not replace every Ruby/platform combination in CI or validate Codecov credentials.
- Establish RubyGems ownership or a pending trusted publisher, and confirm account MFA. The RubyGems name lookup returned 404 on the audit date; that does not reserve the name.
- Review the development-only Puma exceptions when updating `solidus_dev_support`.
- Choose the release version and date, then build and retain the artifact from that reviewed commit. The current metadata intentionally points to its future version tag.

The repository was public when checked. No visibility change was made or is needed for the current metadata links. Publication and any repository visibility decisions remain maintainer actions.
